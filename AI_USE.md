# AI use

ProvenExit was built by Erhan Türker with AI coding assistants. This file says which assistant did what, so a judge
can weigh the work accordingly. Planning documents were generated by Claude; implementation and tests were written by
AI agents task by task, reviewed by Erhan, who made the product and security decisions and ran everything that needs
an account, a key or a payment.

## How the work was split

The hackathon tasks (T01–T30, from that unpublished task list) were executed by an AI **builder** model in
a headless orchestrator (Conductor), one task per commit, each with its acceptance command run and quoted in the
commit or in the build log (not published). The builder worked from the frozen interfaces, not from a free hand: any real-world
disagreement was recorded in that log and escalated to Erhan instead of changing an interface.

The builder's commits are the ones whose message starts with `T<nn>:`. Claude sessions wrote the plan and the earlier
baseline, did the review passes, and ran the testnet/Phala operator work. Commits that are not task commits
(`fix: …`, `e2e: …`) are review follow-ups from those Claude sessions.

## What the AI did not do

- It never held, printed or committed a private key, mnemonic or API token. The exit's operator key exists only as a
  sealed `phala deploy -e` value in the plan; no exit was ever deployed with it (fallback S1-F2).
- It did not deploy the VPN exit, did not push the repository and did not submit the hackathon form.
- It did not decide the product: the name, the pitch, the tracks, the trust model, the fallbacks used (S1-F2) and
  the omissions in `README.md` "What it does not prove" are Erhan's calls.
